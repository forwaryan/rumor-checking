# 可恢复的核查任务

网页提交问题后创建独立的分析任务，并将地址替换为 `?run=<run_id>`。刷新页面或暂时断网后会连接同一任务，不会再次创建分析。已完成的任务直接取回报告。页面仅在内存保留原始输入，地址不再携带问题正文；旧的 `?q=` 链接仍可启动一次分析。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/v1/analysis-runs` | 接收 `AnalyzeRequest`，返回 HTTP 202 和 `AnalysisRun`；编号由服务端生成 |
| `GET /api/v1/analysis-runs/{run_id}` | 查询执行状态、事件游标和已完成报告 |
| `GET /api/v1/analysis-runs/{run_id}/events?after=0` | 从指定游标之后读取 NDJSON；每行是 `{event_id, event}` |
| `POST /api/v1/analysis-runs/{run_id}/resume` | 继续已中断任务，保持编号与原始请求不变 |
| `POST /api/v1/analysis-runs/{run_id}/recheck` | 以完成报告为父版本，对所选声明补证复核 |
| `GET /api/v1/analysis-runs/{run_id}/versions` | 查看同一事项内的版本摘要 |
| `GET /api/v1/analysis-runs/{run_id}/changes` | 查看与直接父版本的判定和证据变化 |
| `POST /api/v1/analysis-runs/{run_id}/cancel` | 停止后续执行，保留已有版本与事件 |

事件编号从 1 开始递增。断线后传最后已处理的编号，重复事件可忽略，跳号需要重新补读。心跳使用 `{type: "heartbeat", run_id}`，不消耗事件编号。完成事件与最终报告持久化后可重新查询。

原有 `/analyze`、`/analyze/stream` 保持请求和响应结构兼容；恢复能力通过新接口提供。所有 HTTP 创建入口都由服务端分配编号并覆盖客户端的 `request_context.run_id`，防止旧接口绕过执行锁写入已有任务的检查点。

## 执行与恢复

状态为 `queued`、`running`、`completed`、`failed`、`interrupted`、`cancelled`。`completed` 表示成功产出报告；报告内的 `insufficient`、`conflicting` 是合法核查结果。运行完成不会使事实结论变得更确定。

后台运行与浏览器订阅分离。关闭页面只结束订阅，不会取消核查。前端对临时断连最多自动重连三次，之后可手动“重新连接”。创建响应丢失时不自动重发创建请求，以避免重复任务。

SQLite 中的原子事务控制创建、容量和恢复；运行持有 30 秒租约，执行期间续租。进程退出后，租约过期的任务在下次访问时标记为 `interrupted`，页面提供“继续核查”。活动或完成任务的恢复请求是幂等的，失败任务返回 409，需要新建。

每个 run 还持有覆盖整个 Pipeline 生命周期的操作系统文件锁：POSIX 使用 `flock`，Windows 使用 `msvcrt.locking`。锁获取和数据库所有权变更在同一个数据库事务内协调。租约过期但旧进程仍在执行或暂停时，恢复返回可重试的 `409 run_still_executing`；旧 Pipeline 退出后才能开始新一代执行。进程死亡由操作系统释放锁。因此旧一代尚未返回的调用或检查点写入不会与恢复后的 Pipeline 并行覆盖同一检查点。

恢复使用同一个 `run_id` 调用现有 Pipeline。设置 `AGENT_CHECKPOINT_ENABLED=true`，并启用深度 Agent 编排后，可以恢复已有步骤检查点；没有可用检查点时会重新执行原请求。恢复不是恰好一次的外部调用保证：已经发出的网络/模型请求无法撤销。执行层租约防止失效任务写入新事件或覆盖最终报告。

## 存储与部署

| 配置 | 默认值 |
| --- | --- |
| `ANALYSIS_RUN_DIR` | `data/analysis_runs` |
| `ANALYSIS_RUN_RETENTION_SECONDS` | `86400`，终态记录保留一天 |
| `ANALYSIS_RUN_MAX_ACTIVE` | `4`，共享数据库中的活动任务上限 |
| `ANALYSIS_RUN_MAX_LLM_CALLS` | `30`，单次 run 的模型调用尝试上限；0 关闭 |

容量满返回 429。过期清理在接口访问时执行，按同一事项最后活动时间整体计算保留期，保证新版仍在使用时父报告可比较。活动任务，以及已经停止或中断但仍持有执行锁的任务不会被清理，且继续占用活动容量。锁释放且整个事项过期后才清理；不存在或过期的编号返回 404。数据库保存恢复所需的请求、事件、报告，目录权限为 0700，数据库和执行锁文件为 0600，默认目录已被 Git 忽略。

这是本机持久化执行层，同机 worker 需要共享 SQLite、执行锁和 checkpoint 目录，存储需要支持本机文件锁语义。租约失效不强制终止旧 Pipeline；若旧调用一直不返回，需要终止对应进程后再恢复。多主机分布式执行、严格终止正在执行的网络调用、完整用户身份与权限管理不在本次实现范围。

`run_id` 是不可枚举的随机编号，也是当前访问记录的凭据；请将任务链接视为私有链接。接口不提供所有用户的全局任务列表。公开部署需由现有网关提供访问控制；恢复功能不会自动新增账号系统。

同一事项的版本共享访问边界：持有其中一个私有 run 链接即可查看该事项的版本和继续复核。不要将单个版本链接当作隔离其他版本的分享权限。

私有 run 响应包含 `raw_input` 完整原始请求，用于刷新后恢复核查入口；`input_preview` 仅供列表式摘要展示，最多 140 字符，不能用作重新核查的输入。原始请求不写入任务 URL。

## 补证和版本

完成报告下可选择有异议的声明、填写最多五个公开网页链接和说明，创建新版本。`claim_indices=[]` 表示复核父报告中的全部声明；最多复核50条，声明类型由父报告继承，观点和预测不会被改成 fact。请求使用 `request_id` 幂等键，重试不重复创建版本。

本轮只输出选中的声明；所选范围在 claim 抽取边界应用，规则判定器只接收调用方显式传入的声明（定向补查时可以是范围内的子集），范围外声明会被拒绝而非静默替换。Agent 综合单次最多接受六条声明，复核范围超过六条时跳过综合、逐条 LLM 判定和可选模型纠错，由规则链核查全部所选声明，不截断为前六条；同名声明按位置消耗模型结果，未产出匹配类型的结果则以证据不足占位。父报告不会被覆盖，未选内容标为“未复核”，其证据不会被误报为删除。比较使用规范化文本精确匹配，不推测改写后的两个句子一定是同一主张。新填写的链接替换本轮补充链接；留空沿用父版本的补充链接，所有旧证据仍可在旧版本查看。普通 fast→deep 按钮仍启动独立的深度分析；“补证复核”入口建立版本关联。

补充说明只记录复核诉求，不能直接充当证据。每个链接都通过逐跳公网校验，连接固定至已验证IP，保留原域名Host与TLS验证，并禁用环境代理；拒绝回环、内网、凭证URL和不安全重定向。抓取失败会留下风险说明。有真实补证时不会将基础mock材料混成live证据。

报告中的 `evidence_snapshots` 与引用偏移一起保存，查看旧版本不会重新抓取来源。版本比较新增 `changed_source_urls`，只表示复核范围内同链接、同提取器留存正文的变化，与模型摘要或引文变化分开。快照仍沿用原报告的私有访问与保留策略，见 [证据快照](evidence-snapshots.md)。

## 停止与预算

停止是明确操作，关闭页面仍只断开订阅。取消或预算耗尽会终止后续工具、重试、模型调用和报告发布；已经发出的外部请求可能要等返回或超时，执行锁与容量不会提前释放。停止的运行不再恢复，继续调查可以从已有完成版本另建复核。

模型调用尝试次数与预留token保存在SQLite中，断点恢复不重置。每次调用前原子检查调用次数和 `AGENT_MAX_TOKEN_BUDGET`（0不限），按输入估算加最大输出保守预留，失败调用也占次数；预留值不是实际账单。覆盖Agent流式模型、轻量判定、结构化抽取及模型检索的调用入口。旧同步/流式兼容API也通过同一manager执行，共享容量、预算与停止策略；返回格式保持Report/平铺NDJSON，响应头包含 `X-Analysis-Run-ID`。

复核强制刷新检索与正文，不读取过期缓存兜底。Agent调用或批次超时及时标记为停止，但执行锁保留到工作线程清退完成。普通网页、浏览器fallback与请求体积的具体限制见 [执行安全](execution-safety.md)。

